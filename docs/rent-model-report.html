1Key insights

  • A flat's own past rent is the best single clue. For flats advertised before, the typical miss on the sealed test was $36.50 (1,903 adverts). For flats never advertised before it was $67.50 (689 adverts). Removing the rent-history clues makes the model $11.80 worse, by far the biggest loss of any clue group. PROVEN
  • Nearby rents matter almost as much. The rent of the 10 nearest flats with the same bedroom count is the clue the model leans on hardest: scrambling it makes the typical miss $49.60 worse. Same-building rents add another $8.60. Location is mostly captured by "what do the neighbours charge". PROVEN
  • Rents rose fast, then levelled off. The median advertised 1-bedroom rent went from $485 (early 2021) to $790 (mid 2026), up about 63%. Most of that rise happened by 2023. Since early 2025 it has moved only about 5%. This likely explains why a "market will keep rising" adjustment did not help. OBSERVED HYPOTHESIS: the "why"
  • A car space adds about $30 a week in our predictions (median over all flats). By bedroom count the model's premium is about $23 / $32 / $26 / $50 (studio / 1 / 2 / 3+ beds). Simple same-building comparisons suggest more ($30–68), but flats with parking also tend to be better flats, so those comparisons overstate it. The model does not lean one way on car-space adverts: on two practice exams its median over- or under-shoot for car and no-car adverts differs by only $1–3. OBSERVED HYPOTHESIS: the raw gap is inflated by flat quality
  • Big flats are hard. The typical miss grows with size: studios $26, 1-bed $34, 2-bed $54, 3+ bed $110. Large flats are rarer, more varied and pricier, so dollar errors are larger. OBSERVED
  • Simple and honest beat clever. Model tuning (14 settings tried), a market-drift adjustment and rounding prices to $5 all made the practice score worse. The default model with good clues won. PROVEN

2The problem, in plain words

Someone is about to advertise a City of Sydney flat for rent in August or September 2026. What weekly rent will they ask? And what would it be with a car space, and without one?

We must give both prices for each of the 65,777 flats in the supplied list. The organisers then compare our price to the real asking rent on 1,699 adverts from 1 Aug to 30 Sep 2026. They use the price that matches the advert (car space or not).

The catch: we may only use information that existed on 31 July 2026. Anything later, even by accident, would make the model look brilliant in testing and fail for real.

Words we use

Typical miss (median error)
Take every prediction's dollar error (ignoring whether it is too high or too low), sort them, and take the middle one. Half our guesses are closer than this, half are further. This is the official score. Lower is better.
Within $100
The share of guesses that land within $100 of the real rent. The tie-breaker. Higher is better.
R² ("R-squared")
How much of the difference in rents between flats the model explains. 1.0 = all of it, 0 = none (as good as guessing the average for everyone). Ours is 0.89.
Clue (feature)
A number we work out for each flat that might help predict its rent, such as "its last advertised rent" or "how many bathrooms".
Practice exam (fold)
A past two-month window where we pretend it is the start of that window, train on everything earlier and predict the window. We had three.
Lockbox (sealed test)
One more two-month window (Jun–Jul 2026) kept sealed until every choice was final. Opened once. Its score is our honest estimate.
Leakage
When information from the future sneaks into a clue. It makes test scores look better than real life. We guard against it everywhere.
Gradient-boosted trees
A standard machine-learning method that builds many small "if this, then that" decision trees, each fixing the errors of the ones before. We used two versions: LightGBM and CatBoost.

4The date split

We test the way the real exam works: learn from the past, predict the next two months. Every choice was made on three practice exams. The fourth window, Jun–Jul 2026, was the sealed lockbox.

RoleTrained on advertsScored on advertsAdverts scored

Fair-test details.

  • Clues are frozen at the window start. The real forecast is made on 31 July and cannot see any August advert. So in each test window, clues are built only from adverts before the window starts. A flat advertised twice inside a window does not "see" its own earlier advert. The model's sense of time is set to one month into the window, like the final run (made as of 1 Aug, time set to 1 Sep).
  • Scored like the real exam. Test adverts are limited to flats in the flats list with a known parking status, and each is scored on the matching price.
  • No data after 31 July 2026 was used anywhere: not in training, clues, tuning or checks. A guard rejects any later-dated row, and a test plants a "future" advert to make sure it is caught. PROVEN

5Methodology

Step by step

  1. Clean the three files (section 3).
  2. Build clues for every advert since 2023 (47,418 training rows), each from earlier adverts only.
  3. Climb a ladder of models, simplest first, so every step has to beat the one before.
  4. Test clue groups: drop existing ones, try new ones, and run a per-clue importance test.
  5. Freeze the choice, open the lockbox once.
  6. Refit on everything up to 31 Jul 2026 and predict each flat twice: car space on, car space off.

The clues (27 in the final model)

GroupClues, in plain wordsWhy we expected it to help
Rent historyThe flat's last advertised rent; months since then; that rent adjusted for market movement since; number of earlier adverts; how its last rent compared to the market then; whether its bedroom count changedThe same flat tends to ask a similar rent next time
MarketMedian rent for the suburb and bedroom count over the last 12 months (city-wide if under 20 adverts)Sets the general level
BuildingMedian rent of other flats in the same building with the same bedrooms, last 12 months (needs 3+ adverts); building's average bedrooms; building's share of flats with parkingSame building, similar rent; building "class"
NeighboursDistance-weighted rent of the 10 nearest same-bedroom adverts of other flats, and their average distanceLocal price level, street by street
Flat factsBedrooms, bathrooms, car space, type, floor, building size, flags for filled-in valuesSize and parking set the base price
LocationLatitude, longitude, distance to the CBDFills gaps where neighbours are sparse
TimeMonths since Jan 2020Lets the model follow the market trend

All "last 12 months" windows end at the start of the advert's month, so they only use earlier adverts.

The model

  • Two tree models, blended. 75% LightGBM (1,400 trees) + 25% CatBoost (2,000 trees), default settings.
  • Aim for the middle, on a percentage scale. The models predict the logarithm of rent (so they learn "10% more" rather than "$100 more") and are trained to hit the median, not the average. The official score is a median, so this targets it directly.
  • Car space: one model, priced twice. Each flat is predicted with car space = 1 and car space = 0. The car-space price is forced to be at least the no-car price, and the gap is capped at $200 a week. (LightGBM cannot enforce "more parking never lowers rent" with this kind of target, so we enforce it after prediction.)
  • No market-drift nudge. We tested scaling prices by recent growth. It made practice scores worse, so the final prices rely on the time clue alone.
  • Rounded to the nearest 50 cents.

7What drives the prediction

To see which clues matter, we scrambled one clue at a time (shuffled its values between adverts) on the practice exams and measured how much worse the typical miss got. A big jump means the model relies on that clue. We repeated the measurement 1,000 times by resampling to get a range, and applied a strict multiple-testing correction (Holm) so that "proven" means proven across 27 tests.

Show as a table

Read with care. Clues that carry the same information share the credit: last rent and adjusted last rent partly cover for each other, so each looks smaller than the pair. The time clue cannot be tested this way, because inside a test window it is the same for every advert. Ten clues are proven. The others are not proven individually, but dropping several together hurt (section 8), so we kept them all.

11Caveats, limits, next steps

  • The real exam will likely be harder than $42. August–September is one to two months further from our data than the lockbox windows, and the 1,699 real adverts may have a different mix (more first-time or larger flats). Our guess for the real score is $50–60. Still well under $86, but not measured. HYPOTHESIS
  • Bigger flats and first-time adverts are weak spots ($110 and $67.50 typical miss). Better size information (floor area) would help most, but we don't have it.
  • The car-space premium is a model estimate, not observed on the same flat. Few flats changed parking between adverts (320 since 2024), so we cannot measure it directly.
  • Training clues are slightly staler than final ones. 12-month windows end at the start of each advert's month, so training rows are on average ~15 days staler than the final rows. Accepted.
  • Small gains are small. The new clue groups improved practice by under $1 in total, close to the noise between windows.
  • Next steps, if time allowed: test the API adverts for the extra 635 flats; a separate model for flats with no history; floor-area data if it can be found from a source dated before the cutoff.

12How to reproduce

From the repo root, with the three raw CSVs in data/raw/ (Windows: .venv/Scripts/python):

python -m src.clean                     # clean flats + adverts -> data/processed/*.parquet
python -m src.train --stage ladder      # baselines, LightGBM, CatBoost (practice exams only)
python -m src.train --stage tune        # random settings search
python -m src.train --stage ablate      # clue-group drop tests
python -m src.train --stage add         # new clue groups
python -m src.importance                # scramble-one-clue test, writes reports/feature_importance.csv
python -m src.train --stage finalize    # blend weight, drift, rounding -> models/chosen.json
#   (sign-off: set "lockbox_ok": true in models/chosen.json)
python -m src.train --stage lockbox     # the one Jun-Jul 2026 score
python -m src.predict                   # refit to 31 Jul 2026, write submissions/rents_FinePrintPredictions.csv
python -m pytest -q                     # tests

Every run is logged in experiments/runs.jsonl with its settings, clue list and data fingerprints. Every decision is in experiments/DECISIONS.md. Random seed fixed in src/config.py.

Privacy. This page shows aggregates only: no addresses, flat ids or individual adverts. Private data stayed on the team machine and was not uploaded anywhere. The page is a single file with no external links or scripts.
